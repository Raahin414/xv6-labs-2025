The page table dump from `pgtbltest` illustrates how xv6 maps a process’s virtual addresses (VAs) to corresponding physical addresses (PAs), along with the permission flags for each page.

The lower region of the address space (around 0x0–0x4000) corresponds to the program’s code and data. Each of these entries points to a valid physical page (for example, va 0x0 → pa 0x87F22000) and includes permissions such as readable, writable, executable, and user-accessible. These sections together form the text, data, and stack segments of the user process.

The middle portion of the address space (0x5000–0x9000) has no active mappings, showing that no physical memory is assigned there.

Near the upper end of the user address space, two special mappings appear that xv6 uses for process–kernel interaction:

* **Trapframe page (va 0x3FFFFFE000)** — stores the process’s CPU register state when traps or system calls occur.
* **Trampoline page (va 0x3FFFFFF000)** — contains common transition code used when switching between user and kernel mode.

This structure demonstrates xv6’s memory layout: user code and data at low addresses, free/unmapped space in the middle, and trap/trampoline pages at the very top that link the user process to the kernel.

The output from `print_pgtbl` displays how each virtual address links to its corresponding physical address through the process’s page table. Every line represents a single page entry and lists the access rights assigned to that page.

0x0000000000000000 → pte 0x...5B

  Matches the user text region visible in `show_pagetable`.

0x0000000000001000 → pte 0x...5B  
  Next user page holding more code or constants.

0x0000000000002000 → pte 0x...D7  
  Writable user page for stack or global data.  
  Permissions: V, R, W, U, A, D. Seen as a data/stack entry in `show_pagetable`.

0x0000000000003000 → pte 0x...07  
  Kernel-only mapping (read + write, not accessible by user code).  
  Restricted to supervisor mode.

0x0000000000004000 → pte 0x...D7  
  Another writable user page for stack/data space.  
  Same permission bits as above: V, R, W, U, A, D.

0x0000003fffffd000 → pte 0x...13  
  USYSCALL region for quick user-level system calls (e.g., getpid).  
  Read-only from user space: V, R, U.

0x0000003fffffe000 → pte 0x...C7  
  Trapframe memory, used by the kernel to save user registers on traps.  
  Kernel read/write only (V, R, W).

0x0000003ffffff000 → pte 0x...4B  
  Trampoline page containing kernel transition code.  
  Read + execute, supervisor-only (V, R, X).

---

Summary:

- **Lower address range (0x0–0x4000)**: holds user memory for code and stack/data.  
- **Higher range (0x3ffffff000 and above)**: reserved for kernel-controlled pages like `USYSCALL`, `Trapframe`, and `Trampoline`.  
- The flags (V, R, W, X, U, A, D) specify validity, allowed actions, and user/kernel accessibility.  

This mapping demonstrates how xv6 separates user pages from kernel memory while still allowing safe interaction between them.
